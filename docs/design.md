# 智控先锋 · 技术设计

> 状态：设计稿。指标为设计目标，尚未在真机实测。

## 1. 目标与非目标

**目标**

- 用一句自然语言完成跨应用的多步骤任务。
- 全流程端侧推理，屏幕与指令不出终端。
- 在 6 GB RAM 的中端手机上运行，断网可完成基础任务。

**非目标**

- 不做产品级 UI、账号体系与商业化。
- 不做多 Agent 协作或云端兜底。
- 不追求所有 App 的泛化，先收敛 1–2 个可演示场景。

## 2. 整体结构

```text
用户指令
   ↓
AccessibilityService → UI 元素树
   ↓  过滤装饰节点、序列化
紧凑文本 + 指令
   ↓
端侧 MiniCPM-V（Q4_K_M）
   ↓  JSON action
动作执行器（click / input / scroll / back / done）
   ↓
重新读取 UI 树 → 下一轮（最多 10 步）
```

## 3. 感知层

### 3.1 UI 树提取

通过 Android `AccessibilityService` 获取当前窗口的节点树，保留：

- 层级与节点类型（按钮、输入框、文本、列表）
- 文本 / contentDescription
- `clickable` / `editable` / `scrollable`
- 屏幕坐标 `bounds`
- 资源 id（如果可得）

过滤不可见、无文本、纯装饰的节点，避免上下文过长。

### 3.2 序列化格式

每个节点一行，编号作为动作目标：

```text
[0] 按钮 "发送" clickable id=send_btn bounds=(320,1200,480,1280)
[1] 输入框 "输入消息" editable id=msg_input bounds=(60,1100,900,1180)
[2] 文本 "微信" id=title bounds=(400,80,600,140)
```

编号只在当前轮有效；每轮重新编号，避免模型记住过期坐标。

## 4. 理解层

- 模型：MiniCPM-V 4.6，Q4_K_M 量化，约 1.6 GB。
- 输入：系统提示 + 用户指令 + 当前 UI 树文本。
- 输出：严格 JSON，单步动作。
- 解码：低温、限制最大 token；输出后用 JSON schema 校验，失败则重试一次。

动作协议：

```json
{"action": "click",  "target": 0, "reason": "发送按钮"}
{"action": "input",  "target": 1, "text": "周五会议改到下午三点"}
{"action": "scroll", "direction": "down", "reason": "更多选项在下方"}
{"action": "back",   "reason": "返回上一级"}
{"action": "done",   "reason": "任务已完成"}
```

约束：

- `target` 必须是当前 UI 树里存在的编号。
- `input` 只能写入 `editable=true` 的节点。
- 发送、支付、删除等敏感动作在执行前弹确认。

## 5. 执行层

- 解析 JSON，映射到 `AccessibilityNodeInfo.performAction`。
- 点击优先用节点动作，失败再按坐标点击。
- 输入用 `ACTION_SET_TEXT`，不模拟逐字键盘。
- 每步执行后等待界面稳定（`AccessibilityEvent` 或固定短延迟），再读取新 UI 树。
- 最多 10 步；超过或连续两次动作无变化则终止并提示。

## 6. 工程化

- 模型量化：Q4_K_M，降低内存占用。
- 上下文压缩：UI 树只保留可操作节点与可见文本。
- 异步预加载：App 启动时预热模型，减少首轮等待。
- 日志：记录每步的 UI 树摘要、动作、耗时，便于回放与调试；日志本地保存。

## 7. 评测计划

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 单步延迟 | 从 UI 树输入到动作输出 | 秒级 |
| 任务成功率 | 完整跑完预设场景的比例 | 先测 1–2 个场景 |
| 内存峰值 | 模型 + App 运行内存 | 6 GB RAM 机型可运行 |
| 离线可用 | 飞行模式下完成基础任务 | 可完成 |
| 误触率 | 敏感动作前确认拦截比例 | 100% 拦截 |

评测集先手工构造 20–30 条指令，覆盖发消息、改设置、填表三类任务；每条记录成功/失败、步数、耗时。

## 8. 风险

- **控件识别失败**：复杂自定义控件没有文本或 id；需要兜底坐标点击与人工接管。
- **模型幻觉**：输出不存在的编号或非法动作；用 schema 校验 + 重试 + 终止策略。
- **无障碍接口差异**：不同厂商 ROM 行为不一致；建立机型兼容矩阵。
- **隐私合规**：屏幕内容可能含敏感信息；端侧处理、最小化日志、明确告知与授权。
- **性能**：中端机内存与算力有限；量化、上下文裁剪、异步加载是前提。
